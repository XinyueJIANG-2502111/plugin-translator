# Hover Translator

Chrome Manifest V3 を使用した、ホバー操作型翻訳拡張機能のプロトタイプです。Web ページ上でマウスポインターが重なっているテキストを検出し、バックグラウンドスクリプトから翻訳サービスへリクエストを送信して、選択した対象言語の翻訳結果をポインター付近に表示します。

本プロジェクトは、OpenAI Codex の支援を受けて開発されました。

## 現在の状態

現在のバージョンは `1.4.3` です。基本的な機能フローと複数回の安定性改善が完了しており、必要な権限、タブ間の設定同期、言語設定、リクエストのタイムアウト、キャッシュ、重複排除、能動的なキャンセル、文字数制限、高頻度イベントの抑制を実装済みです。

一方、正式な翻訳サービスへの移行、プライバシー対応、グローバルなレート制限、自動テストは今後の課題です。

ソースコード内のコメントと UI 用ソースファイルは ASCII 文字に統一し、重要な処理には、その処理が解決する問題を簡潔な英語コメントで記述しています。

## 実装済みの機能

- Chrome Manifest V3 に対応。
- Web ページ上のマウスホバーを監視。
- 約 500 ミリ秒ホバーすると翻訳を開始。
- 通常は「段落モード」として、ポインターが重なった意味的なテキストブロックを優先して取得。
- `Ctrl` キーを押している間、一時的に「文字／単語モード」へ切り替え。
- ポップアップから原文言語と翻訳先言語を個別に選択可能。
- 原文言語は自動検出（`auto`）と英語（`en`）に対応し、追加言語を拡張しやすい構造を用意。
- 翻訳先言語は英語、簡体字中国語、繁体字中国語、日本語、韓国語、スペイン語、フランス語、ドイツ語に対応。
- 翻訳結果をポインター付近のツールチップに表示。
- ビューポート内の空き領域に応じて、ツールチップの表示方向、高さ、水平位置を調整。
- ポインターがツールチップ内にある間は表示を維持し、離れた後に遅延して非表示化。
- ポップアップから拡張機能を有効化／無効化。
- `chrome.storage.local` に有効状態、原文言語、翻訳先言語を保存。
- 明示的に選択した原文言語と翻訳先言語が同一になる組み合わせを禁止し、旧バージョンの競合設定も自動修復。
- ポインターが実際のテキスト範囲に重なっている場合のみ翻訳を開始。
- ポインターが離れた場合や対象テキストが変わった場合、不要になった翻訳リクエストをキャンセル。
- HTTP エラー、ネットワーク障害、レスポンス解析エラーに対する基本的なエラー表示。

## プロジェクト構成

```text
plugin-translator/
├── manifest.json   # 拡張機能のマニフェスト、権限、スクリプト登録
├── background.js   # 翻訳サービスへのリクエストを担当する Service Worker
├── content.js      # テキスト検出、マウス操作、翻訳ツールチップ
├── popup.html      # 拡張機能の設定ポップアップ
├── popup.js        # 設定の読み込み、言語組み合わせの検証、状態保存
├── README.md       # 中国語版ドキュメント
└── README.ja.md    # 日本語版ドキュメント
```

## 処理の流れ

1. `content.js` が対象の Web ページへ挿入されます。
2. ユーザーがテキストを含む要素にマウスポインターを重ねます。
3. コンテンツスクリプトが現在のモードに応じてテキストを抽出します。
4. コンテンツスクリプトが `background.js` に翻訳メッセージを送信します。
5. バックグラウンドスクリプトが Google 翻訳のエンドポイントへリクエストを送信します。
6. 翻訳結果がコンテンツスクリプトへ返され、ツールチップに表示されます。
7. 有効状態、原文言語、翻訳先言語はポップアップから変更して保存できます。

## 実施済みの確認

- すべてのソースファイルと拡張機能マニフェストを確認済み。
- JavaScript ファイルは `node --check` による構文検査を通過。
- `manifest.json` が正常な JSON として解析できることを確認。
- 現在のディレクトリは Git リポジトリではなく、利用可能なバージョン履歴はありません。
- 自動テスト、コードフォーマット／Lint、ビルドフローは未整備です。
- 実際のブラウザーで手動テストを実施済みですが、再現可能な E2E 自動テストはまだありません。

## 実施済みの改善

- Google 翻訳ドメイン向けの `host_permissions` を追加。
- `chrome.storage.onChanged` を使用し、有効状態と設定を開いているすべてのタブへ同期。
- ポップアップからアクティブタブだけに送信していた個別メッセージを削除。
- 翻訳リクエストに 10 秒のタイムアウトを追加。
- 1 回の翻訳対象を最大 1500 文字に制限。
- 同一テキストのメモリーキャッシュと同時リクエストの重複排除を追加。
- リクエスト番号で古いレスポンスを無視し、過去の結果による上書きを防止。
- `requestAnimationFrame` で高頻度のマウス移動処理を集約。
- 一般的な意味的テキストブロックを優先し、入力欄と編集可能領域を除外。
- `Intl.Segmenter` を使用して多言語の単語境界検出を改善。
- DOM のテキスト範囲に対するヒットテストを追加し、コンテナーの余白で翻訳が発生する問題を修正。
- ウィンドウのフォーカス喪失、ページの非表示化、拡張機能の無効化時にショートカットモードをリセット。
- `chrome.runtime.lastError` を処理し、メッセージチャネルのエラーが見落とされる問題を防止。
- 拡張機能のソースコード内にあるコメントと UI 文字列を ASCII 英語へ統一。
- 翻訳先言語のドロップダウンを追加し、選択内容をすべてのタブへリアルタイム同期。
- 原文言語のドロップダウンを追加し、「原文言語 + 翻訳先言語 + 原文」単位でキャッシュを分離。
- 原文言語と自動検出モードに独立した検証処理を追加。
- 原文言語に `Auto` を追加し、新規ユーザーの既定値に設定。
- 翻訳先言語に English を追加し、Japanese が翻訳 API の `ja` コードを使用することを確認。
- 入力欄などの除外領域へポインターが入った際に、古いホバー状態と期限切れ結果を即座に破棄。
- コンテンツスクリプトのメッセージにタイムアウトを追加し、ツールチップが翻訳中のまま残る問題を防止。
- 各翻訳にリクエスト ID を付与し、古いリクエストの利用者がいなくなった時点で実際のネットワークリクエストを中止。
- 明示的な原文言語と翻訳先言語が同一になる設定を禁止し、旧バージョンの競合設定を自動修復。

## 課題管理

### P0：主要機能と信頼性

#### 1. 翻訳サービスのホスト権限（完了）

`manifest.json` では、バックグラウンド Service Worker 向けに `https://translate.googleapis.com/*` の `host_permissions` を宣言済みです。無関係なリモートサービスへの権限は付与していません。

正式な翻訳サービスへ移行する場合は、マニフェストを更新し、引き続き最小権限を維持する必要があります。

#### 2. すべてのタブへの設定同期（完了）

有効状態と言語設定は `chrome.storage.local` を共通のデータソースとして使用し、開いている各ページは `chrome.storage.onChanged` で更新を受け取ります。

拡張機能を再読み込みした後は、古いコンテンツスクリプトのコンテキストを作り直すため、すでに開いていたページを更新する必要があります。

#### 3. 非公式翻訳エンドポイントの評価と置き換え（未対応）

現在は `client=gtx` パラメーターを含む Google 翻訳エンドポイントを使用しています。API キー、安定性保証、クォータ管理、代替手段がないため、仕様変更、レート制限、CAPTCHA などの影響を受ける可能性があります。

正式公開前に、安定性と利用条件を確認できる翻訳サービスを選定し、明確なエラー表示とフォールバック方針を設計する必要があります。

### P1：パフォーマンス、並行処理、データ量

#### 4. マウス監視の負荷軽減（第 1 段階完了）

現在もページ全体の `mousemove` を監視していますが、`requestAnimationFrame` によって処理を 1 描画フレームにつき 1 回へ集約し、テキスト抽出はホバー待機時間の完了後まで遅延しています。複雑なページや再レイアウトが多いページでは、追加のパフォーマンス測定が必要になる可能性があります。

今後は実測結果に基づいて、より厳しいスロットリングや監視範囲の限定を検討します。

#### 5. 翻訳リクエスト数の制御（第 2 段階完了）

同一テキストの結果キャッシュ、同一リクエストの共有、リクエスト番号の検証、能動的なキャンセルを実装済みです。ページが古い結果を必要としなくなった場合は自身の購読を解除し、共有リクエストの利用者が全員いなくなった時点で、バックグラウンドが `AbortController` により実際のネットワークリクエストを中止します。

グローバルなレート制限と同時実行数の上限は未実装です。

残作業：

- 同時実行数の制限とリクエストのスロットリング。

#### 6. 文字数制限とリクエスト方式（部分対応）

意味的テキストブロックを優先し、ページのルートコンテナーを除外したうえで、1 回の翻訳対象を 1500 文字に制限しています。ただし、翻訳リクエストは現在も GET クエリを使用しているため、エンコード後の長いテキストが URL 長の上限に近づく可能性があります。

正式な翻訳サービスの仕様に応じて、POST、分割翻訳、またはより厳しい文字数制限を検討する必要があります。

### P2：操作性とテキスト認識精度

#### 7. 段落認識の改善（第 1 段階完了）

最初にポインターが実際のテキスト範囲に重なっていることを確認し、その後 `p`、見出し、リスト項目、表のセルなどの意味的テキストブロックを優先します。フォーム、編集可能領域、ページのルートコンテナー、拡張機能自身の UI は除外します。

複雑な Web ページ上のカスタムコンポーネントには、より詳細なテキストブロック規則が必要になる可能性があります。

#### 8. 単語境界規則の改善（第 1 段階完了）

現在は `Intl.Segmenter` を優先して単語境界を判定し、Unicode の文字、数字、アポストロフィに対応するフォールバック処理も用意しています。`Intl.Segmenter` を利用できない環境では、連続した中国語文字が 1 つのまとまりとして扱われる可能性があります。

今後、明示的に選択できる原文言語を追加する場合は、言語ごとにより正確なフォールバック規則を追加する必要があります。

#### 9. `Ctrl` モードが解除されない問題（完了）

ウィンドウのフォーカス喪失、タブ切り替え、ページの非表示化、拡張機能の無効化が発生した場合、コンテンツスクリプトが段落モードへ戻すため、`keyup` を受信できなかった場合でも単語モードに残りません。

今後ショートカットに新しい状態を追加する場合も、同じリセット方針を適用します。

#### 10. リクエストタイムアウト（完了）

バックグラウンドのネットワークリクエストには 10 秒、コンテンツスクリプトのメッセージには 12 秒のタイムアウトを設定し、ツールチップが `Translating...` のまま残る問題を防いでいます。

自動再試行は未実装です。追加する場合は、正式な翻訳サービスのエラー分類とレート制限規則に合わせて設計する必要があります。

### P3：製品化と開発基盤

#### 11. 言語設定（第 2 段階完了）

ポップアップから原文言語と翻訳先言語を個別に選択できます。原文言語は自動検出と英語、翻訳先言語は英語、簡体字中国語、繁体字中国語、日本語、韓国語、スペイン語、フランス語、ドイツ語に対応しています。

選択内容は永続化され、開いているすべてのタブへ同期されます。明示的な原文言語と翻訳先言語を同じ値にはできず、UI、コンテンツスクリプト、バックグラウンドの各層で検証します。旧バージョンの競合設定も自動的に移行されます。今後は明示的な原文言語を追加できます。

#### 12. Web ページへのアクセス範囲とプライバシー説明

コンテンツスクリプトは現在 `<all_urls>` に一致するため、アクセス可能なほぼすべての Web ページで動作します。また、ホバーしたテキストは外部の翻訳サービスへ送信されます。

正式公開前に、以下の対応が必要です。

- 対象サイトの権限を縮小できるか評価する。
- どのテキストがどのサービスへ送信されるか明記する。
- パスワード欄、エディター、機密性の高いフォームを処理しない。
- プライバシーポリシーとストア掲載用の権限説明を準備する。

#### 13. 基本的な開発フローの整備

現在はバージョン管理、自動テスト、リリース支援がありません。以下を段階的に追加する必要があります。

- Git リポジトリを初期化し、無視ファイルを設定する。
- 単体テストとブラウザー統合テストを追加する。
- ESLint、Prettier などの静的チェックを導入する。
- 拡張機能のアイコンとストア掲載素材を用意する。
- バージョン更新履歴とパッケージ作成フローを整備する。

#### 14. 単語モードを辞書定義へ変更（未対応）

段落翻訳は維持しつつ、`Ctrl` キーによる単語モードを辞書検索へ変更し、品詞、発音記号、定義、例文を表示する予定です。実装前に、対応する辞書言語、定義の表示言語、データソース、ライセンス、未登録語のフォールバック動作を決める必要があります。

第 1 段階では英単語と英語定義だけに対応し、その後に英中辞書や多言語辞書を検討する方針が現実的です。

## 推奨される実装順序

1. 異なる Web サイト、複数タブ、異常なネットワーク条件での動作検証を続ける。
2. 正式な翻訳サービスとプライバシー方針を決定する。
3. POST または分割翻訳を評価し、長文対応を改善する。
4. グローバルな同時実行数制限とリクエストのスロットリングが必要か評価する。
5. 自動テスト、バージョン管理、アイコン、リリース文書を追加する。
6. 辞書モードを設計して実装する。
7. 原文言語、翻訳先言語、その他の製品機能をさらに拡張する。

## 現在の結論

現在のコードは「ホバーによるテキスト取得 → バックグラウンド翻訳 → ページ上のツールチップ表示」という一連の流れを備え、主要権限、状態の整合性、テキスト範囲の判定、言語組み合わせ、タイムアウト、キャッシュ、重複排除、リクエストキャンセルに対応しています。

次の段階における主なリスクは、非公式な外部翻訳エンドポイント、プライバシー対応、グローバルなレート制限の欠如、実ブラウザーを使用する自動テストの欠如です。これらを解決するまでは、多数のユーザーへ直接公開することは推奨しません。
